# sovet

Два настоящих агента в одном окне tmux: **слева оригинальный Codex TUI, справа оригинальный
Claude Code**. Это те же программы, что запускаются командами `codex` и `claude`, без обёрток.
sovet добавляет общую память проекта, очередь поручений между агентами, уведомления
о правках автора, комментарии chitalka к PDF и Markdown, навыки ARIS и проверки Lean/LongTails.

По умолчанию **Claude — писатель** (меняет файлы), **Codex — ревьюер** (проверяет, файлы
не правит). Роли, точные ID моделей и effort настраиваются для каждого проекта.

Нужны Python 3.11+, tmux ≥ 3.2 и установленные `codex` и `claude` с обычной авторизацией.
Python-зависимостей и отдельных API-ключей нет. Модели не вызываются, пока вы сами
не напишете агенту.

## Быстрый старт

```sh
ln -s ~/code/sovet/bin/sovet ~/.local/bin/sovet   # уже сделано на этой машине
sovet doctor                                      # что найдено в PATH; модели не вызываются
sovet completion zsh --install                    # Tab; для bash: completion bash --install

cd ~/path/to/project
sovet init --programming          # или --math-research для статьи
sovet up
```

Пример статьи (уже инициализирован):

```sh
cd ~/code/sovet/examples/optimization-paper
sovet up --math-research --reader --latex-watch
```

### Первый запуск в новом проекте

Оба CLI работают со своими обычными проверками безопасности, sovet их не обходит:

- **Доверие к папке.** Codex и Claude Code при первом открытии папки спрашивают,
  доверяете ли вы ей. Подтвердите в обеих панелях, если это ваш проект.
- **Хуки в Codex.** Codex показывает четыре команды проекта (`SessionStart`,
  `UserPromptSubmit`, `Stop`, `SessionEnd`, все вида `sovet … hook --role codex --event …`).
  Проверьте и одобрите их в штатном меню `/hooks` самого Codex. Команды одинаковы при
  каждом запуске, поэтому повторное одобрение нужно, только если изменится путь
  проекта, sovet или Python (команда хука содержит эти пути).
- **До одобрения** Codex работает без автоматической подмешки контекста. Общую память и
  поручения он получает через MCP-инструменты `memory_read` и `inbox`. Попросите его:
  «прочитай memory_read и inbox».

В примере `examples/optimization-paper` это уже сделано.

## Что вы увидите

```
┌ Codex · ревьюер · gpt-6.1-sol · high ─┐┌ ▶ Claude · писатель · claude-opus-5-5 · high ┐
│                                        ││                                              │
│   обычный интерфейс codex              ││   обычный интерфейс Claude Code              │
│                                        ││   (курсор здесь)                             │
└────────────────────────────────────────┘└──────────────────────────────────────────────┘
 окна:  agents   watch   chitalka
```

- Главное окно `agents` содержит только две панели 50/50 с подписями на рамке.
  Курсор стоит в панели писателя.
- Панели переключаются щелчком мыши или `Ctrl-b ←/→`. `Ctrl-b z` разворачивает
  одну панель на всё окно и возвращает обратно.
- `watch` (наблюдатель файлов) и `chitalka` — служебные окна. Открыть их:
  `Ctrl-b w`; вернуться: `Ctrl-b w` → `agents`.
- Окно занимает ваш терминал целиком и делится пополам. На узком экране разверните
  нужную панель (`Ctrl-b z`) или подвиньте границу мышью.
- `Ctrl-b d` — отсоединиться. Агенты продолжают работать; `sovet up` вернёт вас.
- Внутри панелей действуют горячие клавиши и slash-команды самих Codex и Claude Code.
  sovet не перехватывает ввод.

## С кем говорить

**Обычно с писателем (Claude, справа).** Ставьте ему задачи, как в обычном Claude Code.
Если хотите независимую проверку, напишите ему «попроси Codex проверить». Или
переключитесь в левую панель и спросите Codex напрямую: он видит те же файлы и ту же
общую память.

Права зависят от роли. Писатель (по умолчанию Claude) работает с обычными правами
своего CLI и вашими настройками: запросы разрешений показывает сам Claude Code.
Ревьюер не меняет файлы. Codex-ревьюер запускается с `read-only` sandbox. Claude
запускается в `plan` **только если** назначен ревьюером (`sovet config --writer codex`).

## Как проходит ревью

1. Писатель вызывает MCP-инструмент `ask_peer`. Поручение попадает в очередь ревьюера.
   Писатель не ждёт ответа и заканчивает свой ход.
2. Ревьюер получает поручение **на своём следующем ходе**:
   - сразу после завершения текущего ответа, если он работал (хук `Stop`);
   - при вашем следующем сообщении в его панели, если он простаивал (`UserPromptSubmit`);
   - когда он сам вызывает инструмент `inbox`.
3. Ответ ревьюера возвращается писателю так же, на его следующем ходе.
4. Глубина взаимных поручений ограничена (`max_peer_depth`), бесконечного пинг-понга нет.

**Важно:** sovet не печатает текст в панели. Простаивающий агент сам ничего не начнёт.
Если поручение ждёт (`sovet status` покажет очередь), переключитесь в его панель и
напишите, например, «проверь inbox».

Из обычного терминала:

```sh
sovet review 'Проверь гипотезы и подсчёт oracle calls'   # в очередь ревьюера
sovet send claude 'Сократи введение до одной страницы'   # в очередь конкретного агента
sovet status                                             # кто открыт, что в очереди
sovet events                                             # общая история
```

## Общая память

- `.team/brief.md`, `state.md`, `decisions.md` — общая память, которую видят оба агента.
- `.team/state.sqlite3` — журнал событий, очередь и ID разговоров.

Хуки передают агенту память и новые события в начале сессии и перед каждым вашим
сообщением. Разговоры и приватные рассуждения агентов не смешиваются: у каждого свой.
Результаты агенты записывают инструментом `memory_append`.

```sh
sovet memory decisions 'Фиксируем стохастический oracle model' --append
sovet edit .team/brief.md
```

## Исследование на ночь

Нативные панели `sovet up` начинают новый ход при сообщении пользователя; для работы
без присмотра предусмотрен отдельный режим:

```sh
sovet night --task RESEARCH_BRIEF.md --hours 8 --max-turns 32 --dry-run
sovet night --task RESEARCH_BRIEF.md --hours 8 --max-turns 32
```

Он использует две отдельные постоянные headless-сессии с моделями/effort проекта:
писатель выполняет следующий шаг, ревьюер проверяет, замечания возвращаются писателю.
На время всего цикла обе роли заняты эксклюзивно. Не совмещайте его с открытыми
нативными панелями **этого проекта**. Их можно заранее закрыть через `sovet stop`;
другие проекты продолжают работать. Режим `up` и его интерфейс не меняются.

`--max-turns` считает ходы обоих агентов, не пары. Ограничение часов распространяется
и на текущий ход; завершение отменённого процесса занимает ещё несколько секунд.
Сетевые сбои повторяются до 3 раз с задержками 15/30/60 секунд. При отклонённом лимите
с известным временем сброса цикл ждёт до этого времени; ожидание входит в `--hours`.
`--retries 0` отключает повторы. Каждая попытка входит в `--max-turns`. Отказ доступа,
неизвестное время сброса лимита или исчерпание повторов останавливают цикл.
Незавершённая очередь и журналы неудачных попыток сохраняются. Контрольный файл — `.team/night/latest.json`,
модельные журналы — `.team/logs/`, результаты и оставшиеся вопросы — `NIGHT_REPORT.md`.
Сам запуск не гарантирует доказанного нового результата: Lean, Comparator и математическое
соответствие постановки проверяются отдельно.

При повторяющихся WebSocket-обрывах можно выбрать для проекта с ChatGPT login
`sovet config --codex-transport http` перед запуском; возврат — `--codex-transport auto`.
Модель и сессия сохраняются, глобальные настройки Codex не меняются.

Чтобы закрытие терминала не прервало работу:

```sh
tmux new-session -d -s research-night -c "$PWD" 'sovet night --task RESEARCH_BRIEF.md --hours 8 --max-turns 32'
tmux set-option -t research-night remain-on-exit on
tmux attach -t research-night
# Ctrl-b d — отсоединиться, оставив работу. Остановить: sovet stop
```

## Правки автора и chitalka

Редактируйте `.tex`, код и Markdown где угодно. Окно `watch` раз в секунду замечает
изменения и записывает diff в журнал. Оба агента получают его на следующем ходе.
Через `sovet edit FILE` правка явно помечается авторской.

С `--reader` в окне `chitalka` работает нативная chitalka: PDF или Markdown с формулами в браузере,
выделения и комментарии. С `--latex-watch` она пересобирает PDF при изменении исходников.
Каждый новый комментарий или уточнение становится задачей писателя.
Писатель правит исходник по `source.file:line`, проверяет сборку и отвечает в той же
карточке (`chitalka_reply`). Как и любая задача очереди, комментарий попадает к
писателю на его следующем ходе. Если Claude простаивал, напишите ему в панели.
Ответы ИИ не создают новых задач. `auto_comments: false` в `.team/config.json` отключает
автоматические задачи по комментариям.

```sh
sovet reader notes.md                         # Markdown: формулы, комментарии, автообновление
sovet up --reader --document notes.md         # запомнить документ для следующих запусков
sovet chitalka list --json
sovet chitalka reply COMMENT_ID 'Исправлено main.tex:42' --done
```

## Программирование или математика

| | `--programming` | `--math-research` |
|---|---|---|
| Инструменты | общая память, ревью, артефакты | плюс Lean/LongTails, Comparator |
| ARIS | навыки сняты (wiki и история сохраняются) | `research-wiki`, `proof-checker`, … |
| chitalka | только с `--reader` | инструменты включены, окно — с `--reader` |

Профиль сохраняется в проекте. Переключение действует для новых сессий агентов
(`sovet up --restart`). Подробности Lean, LongTails и ARIS: [docs/usage.md](docs/usage.md).

## Модели и effort

| Агент | Модель по умолчанию | Effort | Роль |
|---|---|---|---|
| Claude | `claude-opus-5-5` | `high` | писатель |
| Codex | `gpt-6.1-sol` | `high` | ревьюер |

```sh
sovet up --codex-model gpt-6.1-sol --codex-effort xhigh --claude-effort high
sovet config --writer codex      # поменять роли
sovet config                     # показать текущий конфиг
```

Флаги записываются в `.team/config.json` **этого проекта**. Глобальные настройки
Codex и Claude не меняются. Модель передаётся точным ID, без подмены. Доступность модели
и effort проверяет сам провайдер при запуске; `doctor` этого не проверяет.
Запущенный агент получит новые модель и effort только после `sovet up --restart`.
Подписи на рамках обновляются при любом `sovet up`.

## Вернуться, перезапустить, остановить

```sh
sovet up               # открыть или вернуться; перезапускает только упавшие панели
sovet up --detach      # запустить или починить сессию в фоне
sovet up --restart     # перезапустить оба агента и службы в этой tmux-сессии
sovet up --dry-run     # показать команды tmux, ничего не менять
sovet status           # человекочитаемо; --json для скриптов
sovet sessions         # все запущенные сессии sovet (из любой папки), или sovet ps
sovet stop             # остановить всё, что sovet запустил для текущего проекта
sovet stop sovet-optimization-paper-3818f4   # сессия по ID из sovet sessions
sovet stop 51732                             # один процесс по PID
sovet stop --all                             # все сессии sovet этого пользователя
sovet stop --all --force                     # плюс SIGKILL тем, кто не завершился
```

- **Разговоры сохраняются.** Если вы выйдете из Codex или Claude, панель останется
  с пометкой «Pane is dead». `sovet up` запустит агента снова и продолжит тот же
  разговор (`--resume`/`resume` по сохранённому ID).
- `--restart` прерывает текущие ходы агентов. Память `.team/`, очередь и истории
  разговоров не затрагиваются. Другие tmux-сессии и проекты тоже не затрагиваются.
- **Старая сессия с curses-панелями** (до перехода на нативные TUI) переводится
  обычным `sovet up` на месте. Исключение: старая панель ещё выполняет задачу. Тогда
  `up` откажется, потому что замена оборвала бы ход посреди правок, и попросит
  `sovet up --restart`.
- При первом таком переходе каждый агент начинает **новый** нативный разговор.
  Огромный пакетный разговор старых панелей в TUI не подгружается. Старая история
  остаётся: ответы — в `sovet events`, ID прежних разговоров — в `.team/state.sqlite3`
  (metadata `legacy:ROLE:session`). Дальше `sovet up` продолжает уже нативные разговоры.
- `sovet stop` без аргументов останавливает **все** процессы sovet этого проекта, включая
  идущий `sovet research setup` (загрузка Mathlib). Если загрузка нужна, дождитесь её
  или закройте только tmux: `tmux kill-session -t ИМЯ` (имя — строка `tmux:` в `sovet status`).
- `sovet stop` опирается на `ps`. Перед каждым сигналом он проверяет UID, время запуска
  и команду процесса. Сторонние сессии Codex и Claude не трогает.

## Tab-автодополнение

`sovet completion zsh --install` (или `bash`) добавляет помеченный блок в `~/.zshrc`.
Повторная установка заменяет только его. Дополняются команды, флаги, роли, effort,
пути, ID запущенных сессий, цели Lean и ID комментариев chitalka. Модели при этом
не вызываются. Для текущего терминала: `source ~/.local/share/sovet/completion/sovet.zsh`.

## Что происходит автоматически

| Автоматически | Только по вашему действию |
|---|---|
| память и новые события подмешиваются в начале сессии и перед вашим сообщением | первый ход агента после запуска или простоя |
| правки файлов попадают в журнал (окно `watch`) | перезапуск после смены модели (`--restart`) |
| комментарии chitalka становятся задачами писателя | исполнение задачи простаивающим агентом |
| ждущая задача подхватывается сразу после завершения хода (Stop) | полная сборка LongTails |
| ответ агента на задачу возвращается автору задачи | |

## Ограничения

- Доставка в простаивающую панель отсутствует намеренно: sovet не эмулирует
  нажатия клавиш. Нужен ваш ход в этой панели.
- Пока хуки Codex не одобрены в его `/hooks`, Codex не получает контекст автоматически.
  Ему остаются MCP-инструменты `memory_read` и `inbox`; ждущие задачи видны в `sovet status`.
- Защита `artifact_write` по SHA действует для записей через sovet. Встроенные
  Edit/Write агентов и внешние редакторы этой блокировкой не пользуются. Поэтому агенты
  получают правило перечитывать файл перед правкой.
- `mouse on` включается только для этой tmux-сессии. Прокрутка колесом уходит в copy-mode
  tmux, если TUI сам не обрабатывает мышь.
- Если в конфиге tmux отключён alternate screen (`terminal-overrides … smcup@:rmcup@`),
  перерисовки TUI могут оставаться в истории прокрутки терминала.
- `.team/claims.json` — рабочий реестр утверждений. sovet не объявляет их доказанными.
  Компиляция Lean и аудит Comparator — разные проверки (см. docs/usage.md).
