# Ревью UX и реализации sovet (Claude, писатель)

Проверено состояние коммита `80bc767`. Основной сценарий:
`cd examples/optimization-paper; sovet up --math-research --reader --latex-watch`.
Ниже ошибки отсортированы по важности. Метки: **P0** — нарушает главное требование,
**P1** — пользователь путается или теряет работу, **P2** — шероховатость.

## Главный провал

**P0. Главное окно — самодельный чат, а не Codex и Claude Code.**
Пользователь просил две настоящие интерактивные программы рядом. `sovet up` открывал две
curses-панели (`sovet/ui.py`). Каждая панель — строка ввода и журнал поверх очереди SQLite.
Ход выполнялся невидимым `codex exec --json` / `claude -p --output-format stream-json`.
Из-за этого:

- нет ни одной возможности оригинальных TUI: slash-команд, выбора модели, диалогов
  разрешений, истории, вставки изображений, `/resume`, Esc-прерывания, diff-просмотра;
- вместо работы агента видна выжимка: текст ответа и строки `· Bash`, `· mcp_tool_call`;
- права выданы молча: `acceptEdits` для писателя и `dontAsk` для ревьюера. Человек не
  видит запросов разрешений и не может их отклонить;
- Enter не отправляет сообщение модели, а только ставит задачу в очередь. Ответ приходит
  целым блоком после завершения хода;
- собственные горячие клавиши (`/ask`, `/sync`, `/status`, PgUp/PgDn, Ctrl+C = отмена хода)
  конфликтуют с привычками пользователя tmux и обеих CLI.

Это провал архитектуры, а не оформления. Цвета и подписи его не исправят. Самодельный
интерфейс нужно было убрать из главного окна полностью. Это сделано (см. «Изменения»).

## P1

1. **Фокус на ревьюере.** После запуска курсор стоял в левой панели Codex. Говорить
   пользователь чаще всего будет с писателем, а это Claude справа.
2. **Окно 80×24 и неравные панели.** `new-session -d` без `-x/-y` создаёт окно 80×24.
   После `split-window -h` получаются панели по ~40 колонок, layout не выравнивается.
   Настоящему TUI Codex/Claude такой ширины мало.
3. **Панели без подписей.** tmux не показывал, где какой агент, его роль и модель.
   Опознать их можно было только по заголовку внутри curses.
4. **Повторный `up` ничего не чинит.** Если сессия существовала, панели не проверялись.
   Умершая панель исчезала: `remain-on-exit` был выключен, и раскладка ломалась.
   Старая panel-сессия оставалась старой после обновления кода. `--restart` и миграции не было.
5. **Флаги reader при живом окне игнорировались.** `--latex-watch`/`--pdf` при существующем
   окне `chitalka` пропускались без предупреждения.
6. **Нет проверки бинарников.** Без `codex` или `claude` в PATH панель мгновенно падала,
   окно закрывалось, и ошибку нельзя было прочитать.
7. **Нечитаемый `status`.** Команда печатала сырой JSON с 50 задачами, включая полные prompt и
   result. Не было видно, какие агенты работают, где tmux-сессия и что ждёт в очереди.
8. **`send`/`review` печатали голое число.** Не объяснялось, кто и когда выполнит задачу.
   В нативной схеме фонового исполнителя нет, и такая задача молча копилась бы.
9. **Невидимые headless-исполнители.** Панель одновременно была worker-ом своей роли.
   При нативных TUI фоновый `run` для той же роли привёл бы к двум процессам
   в одном разговоре (resume одного session ID) и к двум писателям.
10. **README обещал больше, чем есть.** «workers продолжают работать без открытого
    терминала», «Ctrl+b ←/→» как единственная навигация, описание `/ask` и `/sync` —
    всё это относится к удалённой модели. Не было раздела «что вы видите после запуска».

## P2

- Сообщение `up` печаталось прямо перед `attach` и сразу исчезало за экраном tmux.
- `up` без TTY (из скрипта) падал на `attach` с «not a terminal» вместо detach с подсказкой.
- Внутренние команды (`panel`, `run`, `mcp`, `watch`) показывались в `--help` и в Tab.
- Описание `sovet --help` («Claude пишет, Codex проверяет») не зависит от `writer`.
- `kill-window -t name:chitalka` использует неточное совпадение имени сессии (без `=`).
- `processes.legacy()` не знал `native`: fallback-обнаружение без реестра не видело бы
  нативные панели. Исправлено родителем.
- `sovet/ui.py` больше нигде не использовался; родитель удалил его.

## Изменения (Claude)

Изменённые файлы: `sovet/cli.py`, `sovet/completion.py`, `sovet/sessions.py`, `README.md`,
`docs/usage.md`, `docs/architecture.md`, этот файл, новый `tests/test_native_ui.py`.

- **Главное окно `agents`** содержит ровно две панели:
  слева `launch_command(project, "native", "codex")`, справа `… "native", "claude"`.
  `sovet native ROLE` ждёт до 20 с, пока прежний процесс роли (например, заменяемая
  curses-панель) освободит `worker-ROLE.lock`, затем вызывает лениво импортированный
  `sovet.native.run_native`. Launcher регистрируется как `launcher:ROLE`, сам harness —
  как `native:ROLE` (это делает `run_native`).
- Старая `panel ROLE` стала скрытым синонимом `native ROLE`. `up` никогда не запускает
  `ui.py`, `run` и headless-исполнителей.
- Подключены точки входа, которые использует `native.py`: `sovet hook --role --event`
  (→ `bridge.main_hook`) и `sovet mcp --native`.
- Размер нового окна равен реальному размеру терминала (например, 120×35), без
  увеличения: окно больше экрана обрезалось бы или требовало прокрутки. При `--detach`
  и без TTY — 160×45 вместо 80×24 tmux. При каждом `up` выполняется
  `select-layout even-horizontal`. На узком экране помогают `Ctrl-b z` и мышь.
- Панели и окна находятся по `@sovet_role`/`@sovet_window` и по ID; индексы не используются.
  Окно сначала создаётся с заглушкой, затем включается `remain-on-exit`, и только потом
  запускается программа. Сразу упавший агент оставляет на экране свою ошибку.
- Подписи на рамках берутся из `@sovet_label`. `mouse on` включается только для этой
  сессии (проверено тестом на чужой сессии). Фокус — на писателе.
- Повторный `up` запускает упавшие панели заново, создаёт недостающие с нужной стороны,
  обновляет подписи и возвращает 50/50. Живые нативные панели не трогаются.
- **Миграция curses-сессии**: обычный `up` заменяет старые `panel` на месте, в той же
  tmux-сессии. Если по очереди идёт `running`-задача, `up` отказывается: старая панель
  посреди headless-хода оборвала бы правку. Нужен явный `--restart`. Другие tmux-сессии,
  `research setup`, `.team/` и истории не затрагиваются. При первом переходе агент
  начинает новый нативный разговор; ID пакетного разговора сохраняется в
  `legacy:ROLE:session` (это делает `native.py` родителя), ответы остаются в `sovet events`.
- `up --restart` перезапускает агентов, watch и chitalka в этой сессии.
  `up --dry-run` печатает команды tmux и ничего не меняет, даже конфиг.
- `--pdf` и `--latex-watch` подразумевают `--reader` и запоминаются (`reader_options`).
  Простой `sovet up` открывает chitalka так же. Если окно chitalka живо, а флаги другие,
  выводится предупреждение.
- `run ROLE` отказывается работать, если роль открыта. Занятая блокировка выдаёт
  понятную ошибку вместо `Errno 35`.
- `status` по умолчанию человекочитаемый (tmux, роли с PID и ID разговора, службы,
  очередь, способ доставки); есть `--json`. `send`/`review` объясняют доставку; есть
  `--json`. `sessions` подписывает виды процессов по-русски.
- В `--help` и Tab видны только пользовательские команды.

### Проверка

- `python3 -m unittest tests.test_native_ui`: 17 тестов. Используется настоящий tmux
  на отдельном сокете (`TMUX_TMPDIR`) через обёртку `tmux -f /dev/null`, без изменения
  `HOME`; `XDG_CONFIG_HOME`/`XDG_STATE_HOME` временные. Условия: `base-index 7`,
  `pane-base-index 3`, посторонняя сессия. Вместо агентов — заглушки `sleep`.
  Проверены: 50/50, порядок, фокус, подписи, повтор `up`, перезапуск упавшей панели,
  восстановление удалённой, миграция curses, отказ при `running`, chitalka и
  programming, dry-run, `run_native`/hook/mcp, `run`, `status`, `send`, Tab.
- Полный `python3 -m unittest discover -s tests`: 51 тест, OK (с текущим `bridge.py` родителя).
- `sovet up --dry-run` для живой сессии примера: только теги, подписи и layout;
  ни одного `respawn-pane`, то есть живые агенты не трогаются.
- Родитель проверил на реальном экране демо: оригинальные Codex и Claude Code,
  79/80 колонок, фокус на писателе справа. Доверие к папке и четыре хука Codex одобрены
  через штатный `/hooks`, без обходных флагов.
- Один раз, пока тестовый сервер читал `~/.config/tmux/tmux.conf`, `respawn-pane`
  завершился с `fork failed: Device not configured`. Повторить не удалось; после изоляции
  конфига тесты стабильны (3 прогона подряд). Root стоит обратить внимание, если ошибка
  появится на экране.

### Остающиеся ограничения

- В простаивающий нативный TUI ничего не доставляется само: нужен ход пользователя или
  завершение текущего хода (Stop). Это ограничение схемы без эмуляции клавиш.
  Комментарий chitalka при простаивающем Claude ждёт сообщения в его панели.
- Codex исполняет четыре хука проекта только после одобрения в его штатном `/hooks`;
  до этого остаются MCP `memory_read`/`inbox`. Это обычная защита Codex, а не шаг sovet.
  Команды хуков стабильны, но содержат пути проекта, sovet и Python: при их смене
  Codex спросит снова.
- На узком терминале каждая половина уже 80 колонок. Оба TUI работают, но тесно.
- Смена модели или effort попадает в запущенный TUI только после `--restart`,
  а `--restart` прерывает текущие ходы обоих агентов. Перезапуска одной роли нет.
- `sovet stop` без аргументов останавливает и `research setup` проекта (так было и раньше;
  в README есть предупреждение).
- У пользователя в tmux отключён alternate screen (`smcup@:rmcup@`). Перерисовки TUI
  могут засорять историю прокрутки. sovet это не меняет; в README есть заметка.
